# Cloud Service Models: IaaS, PaaS, and SaaS

Cloud service models describe the kind of service a provider offers and how responsibilities are divided between the provider and the customer.

## 1. IaaS — Infrastructure as a Service

IaaS provides fundamental computing resources such as virtual machines, storage, and networking.

**Simple example:** Renting a cloud virtual machine to host a website.

**Customer responsibility:** Depending on the service, customers commonly manage the operating system, applications, data, and many configuration choices.

## 2. PaaS — Platform as a Service

PaaS provides a managed platform and tools that help developers build, deploy, and run applications without managing all the underlying infrastructure.

**Simple example:** Deploying application code to a managed application platform.

**Customer responsibility:** Customers usually focus on their application and data, while the provider manages more of the underlying platform.

## 3. SaaS — Software as a Service

SaaS provides ready-to-use software over a network, often through a web browser or app.

**Examples:** Gmail and Facebook are commonly used examples of online software services.

**Customer responsibility:** Users generally manage their accounts, settings, and the data they contribute, while the provider operates the application.

## Comparison

| Model | What the provider offers | What the user mainly does |
|---|---|---|
| **IaaS** | Virtualized infrastructure | Configures systems and runs applications |
| **PaaS** | Managed application platform | Builds and deploys applications |
| **SaaS** | Ready-to-use software | Uses and configures the application |

## Easy way to remember

- **IaaS → Infrastructure**
- **PaaS → Platform**
- **SaaS → Software**

As a general rule, IaaS gives the customer more infrastructure control, while SaaS gives the customer a ready-to-use application. PaaS sits between them.

## Real-world note

Services such as Uber and food-delivery platforms use software and cloud technologies to operate at scale. Their exact architecture and mix of service models may vary; a familiar app should not be assumed to use only one model.

## Key takeaway

The three models differ mainly in how much the provider manages and how much the customer configures or builds.
